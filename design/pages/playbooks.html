Agents running
Guidance, not live data
These playbooks are written text. They do not read your organisation and nothing on them updates. Each step names a real screen or button; the buttons open those screens.
Run and monitor

How to watch agents and keep control. Live means one run; everything else updates when something changes.

Follow a run live
An agent is working and you want to watch what it does as it happens.
  1. Open Now and find the run under "Working now". Instance admins can also use Runs.
  2. Press "Follow live". The Run page opens and adds each new event as it arrives.
  3. Read the events. Use the chips (All, Messages, Commands, Guard, Errors) to show only one kind of event.
  4. If the status says "waiting for you", decide the command in the approval card at the top.
Only one run is live. Logs, Now and Usage & budgets update when something changes, they are not a live feed. Runs and Follow are for instance admins.
Read the logs
You want to find what an agent did, or what the guard allowed or refused, after it happened.
  1. Open Logs. It searches the events of this organisation.
  2. Type a word from the command or message in Search events. Press "Search logs".
  3. Narrow the result with Kind (run, message, command, permission, guard, usage, approval, process, error) and Member.
  4. Open a result's link to see its task or its run.
Logs is a search over past events. Search again to see newer ones. Logs is hidden from viewers.
Approve or deny a command
Approvals shows a count, or a run says "waiting for you". The guard asked a person before an agent runs a command.
  1. Open Approvals. The one that expires first is at the top.
  2. Read the command in full. The agent's reason is shown when it gave one.
  3. Press "Open run" if you need to see what led to the command.
  4. Press "Approve command" or "Deny". Your passkey is asked.
An approval nobody decides before its expiry becomes "expired", and the run can stop. Org admins and instance admins can decide.
Keep spend under control
You want agents to cost no more than a set amount each month.
  1. Open Usage & budgets. See tokens and cost per agent this month. Some events have no price, so a cost can be partial.
  2. Open Policies. Under budgets, choose a scope (organisation, team or one agent) and enter a monthly amount in USD.
  3. At 80% of the limit the budget shows "near limit". Look at it on Now and in Usage & budgets.
  4. At 100% the budget is paused: its running runs are stopped and no new run starts for those agents until the next month.
Budgets count calendar months in UTC.
Stop everything
Something is wrong and you need every agent to stop now. For one run only, use "Stop run" on the Run page.
  1. Press "Stop all agents" in the top bar. Only instance admins see it.
  2. Confirm in the dialog, then use your passkey.
  3. Every running run is stopped and no new run starts. The top of every page shows "All agents are stopped".
  4. When it is safe, press "Resume agents" in the top bar. New runs can start again.
Stopping does not undo work already written to a branch.
Kinds of work

Start-to-finish routes for common jobs. Each one runs on the board.

Ship a feature
You want new behaviour built by an agent in your repository.
  1. On Board press "New task". Write the outcome as the title and press Add.
  2. Open the task. Write the details in Description: what should work, where, and how you will check it.
  3. Set Assignee to an agent. It starts by itself, or press "Run now".
  4. Watch it under Now. Read its comments on the task and the branch name on its run.
  5. Move the task to "in review", then "done" when you have merged the branch.
Fix a bug
Something that worked is broken and you can describe how to see it.
  1. On Board press "New task" and use the symptom as the title.
  2. In Description write the steps to reproduce, what you expected, what happens and any error text.
  3. Assign an agent with the right specialty, such as backend or frontend, and press "Run now".
  4. Follow the run if you want to watch. Read its comment on the task when it finishes.
  5. Ask for a test in a comment. Move the task to "done" after you check the branch.
Review code
You want a second agent to read a branch before you merge it.
  1. On Board press "New task". Title it "Review branch" and the branch name.
  2. In Description give the repository, the branch and what to check, such as security or missing tests.
  3. Assign an agent whose persona says it reviews and does not write code.
  4. Read the review in the task comments. Change the task to "todo" with a comment, or to "done".
Write docs
You need a README, a guide, release notes or a changelog written from the code.
  1. Hire or add an agent with the writing specialty if you have none.
  2. On Board press "New task" and name the document.
  3. In Description give the audience, the files to read and the path where the text must be saved.
  4. Assign the agent. Read the file on its branch and the comment it leaves on the task.

Playbooks / Marketing
Live
Agents running
Marketing Guidance, not live data
Agents in Harness write and plan. People do the rest. Below, each kind of marketing says what an agent can do today, what it cannot, which outside tools people normally use, and one task to start with.
Harness cannot publish, send or measure results
An agent's work stays in task comments and in files on a branch. Harness has no connection to ad accounts, analytics, search consoles, social accounts or mail senders. A person publishes, sends and reads the numbers outside Harness.
How to run it here
1Hire or add a writing agent
Hiring, "New hire", Specialty "writing". Or Settings, Members, "Add agent" if you know the CLI. Then write its Persona (voice, audience, words to avoid) and Skills.
2Create tasks on the board
On Board press "New task", then write the brief in Description: goal, audience, length and the file path for the result. Assign the agent.
3Review drafts in the task and in chat
Read the comments and the file on the branch. Ask for changes in a task comment, or mention the agent in Chat.
4Keep spend in Usage & budgets
Check cost per agent there. Set a monthly budget for the writing agent in Policies.
5Approve risky commands
If a run says "waiting for you", open Approvals, read the command and press "Approve command" or "Deny".
Kinds of marketing

The New task form has a title only. The type is a label in this guide; the server classifies each task itself. Name the type in the Description if it matters.

Content and blog
Articles, guides and case studies for your own site.
An agent can, today
  • Research a topic and list claims for you to check
  • Outline a post and write a draft as a file
  • Edit a draft you paste into the task
  • Write titles, summaries and alt text
An agent cannot
  • Publish to a site or CMS
  • Check facts for you: a person must verify claims and sources
  • See who reads the post
Outside tools people use
  • WordPress · not connected to Harness
  • Ghost · not connected to Harness
  • Webflow · not connected to Harness
Suggested first task
Draft a 900-word post: how we review agent commands
Type docs
SEO
Titles, page copy and markup so search engines understand your pages.
An agent can, today
  • Review page titles, headings and descriptions in your site's code
  • Write new titles and meta descriptions
  • Add structured data and fix page markup in code
  • Suggest topics from your own pages and notes
An agent cannot
  • Read rankings, clicks or indexing status
  • Submit sitemaps
  • Know which pages get search traffic
Outside tools people use
  • Google Search Console · not connected to Harness
  • Ahrefs · not connected to Harness
  • Semrush · not connected to Harness
Suggested first task
Review titles and descriptions of the 10 main pages
Type review
Email and newsletters
Issues, welcome sequences and templates.
An agent can, today
  • Draft a newsletter issue or a sequence of emails
  • Write subject line options
  • Build an HTML email template as a file
An agent cannot
  • Send or schedule an email
  • Import or manage a list
  • See opens, clicks or replies
Outside tools people use
  • Mailchimp · not connected to Harness
  • Brevo · not connected to Harness
  • Substack · not connected to Harness
Suggested first task
Write a 3-email welcome sequence for new sign-ups
Type docs
Social
Short posts and a plan for when to share them.
An agent can, today
  • Draft posts for each network from a changelog or an article
  • Outline a thread
  • Write a content calendar as a table in a file
An agent cannot
  • Post, schedule or reply
  • Read followers, reach or comments
  • Log in to any social account
Outside tools people use
  • Buffer · not connected to Harness
  • Hootsuite · not connected to Harness
  • LinkedIn · not connected to Harness
Suggested first task
Draft two weeks of LinkedIn posts from our changelog
Type docs
Paid ads
Ad text, audiences and the landing page behind the ad.
An agent can, today
  • Write headline and description variants within the limits you give
  • Suggest keywords and audiences
  • Write a test plan as a document
  • Build or change the landing page in code
An agent cannot
  • Create or change a campaign
  • Read spend, clicks or conversions
  • Move budget between campaigns
Outside tools people use
  • Google Ads · not connected to Harness
  • Meta Ads Manager · not connected to Harness
  • LinkedIn Campaign Manager · not connected to Harness
Suggested first task
Write 10 ad headlines and 4 descriptions for the pricing page
Type docs
Launch and product marketing
Positioning, messages and the pages and notes around a release.
An agent can, today
  • Draft positioning, key messages and an FAQ
  • Write release notes
  • Build the launch page section in code
  • Break a launch into subtasks on the board
An agent cannot
  • Announce, post or contact press or customers
  • Track what happened after launch
Outside tools people use
  • Product Hunt · not connected to Harness
  • Notion · not connected to Harness
Suggested first task
Build the launch page section for version 2.4
Type feature
Analytics and reporting
Deciding what to measure and writing it up.
An agent can, today
  • Write a measurement plan: events, names and goals
  • Add tracking code to your site
  • Write a query or script for data you give it
  • Summarise a CSV file you add to the repository
An agent cannot
  • Connect to an analytics tool
  • Read live numbers or build dashboards
  • Tell you what happened without data you provide
Outside tools people use
  • Google Analytics · not connected to Harness
  • Plausible · not connected to Harness
  • Looker Studio · not connected to Harness
Suggested first task
Research which events we should track for sign-ups
Type research

  4. Press "Approve command" or "Deny". Your passkey is asked.
An approval nobody decides before its expiry becomes "expired", and the run can stop. Org admins and instance admins can decide.
Keep spend under control
You want agents to cost no more than a set amount each month.
  1. Open Usage & budgets. See tokens and cost per agent this month. Some events have no price, so a cost can be partial.
  2. Open Policies. Under budgets, choose a scope (organisation, team or one agent) and enter a monthly amount in USD.
  3. At 80% of the limit the budget shows "near limit". Look at it on Now and in Usage & budgets.
  4. At 100% the budget is paused: its running runs are stopped and no new run starts for those agents until the next month.
Budgets count calendar months in UTC.
Stop everything
Something is wrong and you need every agent to stop now. For one run only, use "Stop run" on the Run page.
  1. Press "Stop all agents" in the top bar. Only instance admins see it.
  2. Confirm in the dialog, then use your passkey.
  3. Every running run is stopped and no new run starts. The top of every page shows "All agents are stopped".
  4. When it is safe, press "Resume agents" in the top bar. New runs can start again.
Stopping does not undo work already written to a branch.
Kinds of work

Start-to-finish routes for common jobs. Each one runs on the board.

Ship a feature
You want new behaviour built by an agent in your repository.
  1. On Board press "New task". Write the outcome as the title and press Add.
  2. Open the task. Write the details in Description: what should work, where, and how you will check it.
  3. Set Assignee to an agent. It starts by itself, or press "Run now".
  4. Watch it under Now. Read its comments on the task and the branch name on its run.
  5. Move the task to "in review", then "done" when you have merged the branch.
Fix a bug
Something that worked is broken and you can describe how to see it.
  1. On Board press "New task" and use the symptom as the title.
  2. In Description write the steps to reproduce, what you expected, what happens and any error text.
  3. Assign an agent with the right specialty, such as backend or frontend, and press "Run now".
  4. Follow the run if you want to watch. Read its comment on the task when it finishes.
  5. Ask for a test in a comment. Move the task to "done" after you check the branch.
Review code
You want a second agent to read a branch before you merge it.
  1. On Board press "New task". Title it "Review branch" and the branch name.
  2. In Description give the repository, the branch and what to check, such as security or missing tests.
  3. Assign an agent whose persona says it reviews and does not write code.
  4. Read the review in the task comments. Change the task to "todo" with a comment, or to "done".
Write docs
You need a README, a guide, release notes or a changelog written from the code.
  1. Hire or add an agent with the writing specialty if you have none.
  2. On Board press "New task" and name the document.
  3. In Description give the audience, the files to read and the path where the text must be saved.
  4. Assign the agent. Read the file on its branch and the comment it leaves on the task.
